# 进度台

用已有证据帮助用户了解主任务，保持主会话的工作现场。查询不发送消息、不唤醒主 agent，也不替它执行、评审或调度。目标已经暂停或结束时，同样可以查看最近结果。

## 确认查看对象

沿用用户指定或本会话已经确认的项目、目标与主会话。缺少信息时，先核对当前项目、`.retro/sessions/*.json`，或平台提供的会话列表；存在多个合理候选时再请用户选择。工作目录相同不代表是同一个任务，不默认选择最近活动的会话。

本 skill 与 `retro` 通常相邻安装。使用相邻目录的 [retro.mjs](../retro/scripts/retro.mjs)，无需加载主协调 skill 或创建 `/goal`。先用 `records show --session <主会话ID>` 定位目标目录，再读其 PROGRESS.md。多个活跃目标时明确选择会话，不按最近修改时间猜测。找不到脚本时，只读已确认目标目录内的快照、报告和对应会话摘要，说明缺少哪些观测，不自行安装或启动监控。

## 按问题取证

先运行 `node "<retro 目录>/scripts/retro.mjs" status --session <主会话ID> --root "<项目绝对路径>"` 取得概览，再只补读回答问题需要的证据：

- 当前工作与阻塞：主会话最近的消息、工具状态和任务报告。
- 某个任务或结果：`<目标目录>/tasks/<任务>/report.md`、相关 notes、结果表与验证记录。
- 路线和待决定事项：进度快照、`<目标目录>/route-review.md`、ideas.md 或 backlog.md 的相关部分。
- 运行效率：`metrics` 命令与相应时间窗口的日志；过程指标不等于任务收益。

`status`、`metrics` 都支持 `--session <主会话ID>`；有多个活跃目标时必须指定。报告按该会话的目标目录读取；运行事件日志仍是项目级观测，不能把整个项目的统计归给某个任务。需要补充细节时，使用对应文件或平台的只读会话接口。Codex 桌面有 `read_thread` 时可按 ID 读取；不要发消息去问主 agent。

大日志先用关键词定位或读末尾，不整份载入。摘要、报告标题和文件路径只是线索；支撑结论的结果或错误要读到原始记录。记录缺失、缓存过时或文件不可读时，明确说无法确认，不能据此断言任务已停、已完成或没有进展。

## 怎么回答

先回答用户的问题；通常说明当前在做什么、最近得到什么结果、下一步或阻塞是什么即可。给关键证据的路径或时间，需要用户决定的事项单独指出，不照抄整个状态快照。

- 区分**查询时间**与**来源最后更新时间**，按用户时区表述；刚运行 `status` 不代表里面的缓存刚更新。
- 区分目标状态、主会话轮次与执行者状态：goal active 不保证主 agent 正在运行，执行者有输出也不证明任务有实质进展。
- 无活动、空闲名额、阶段超时都是线索，不能单独证明卡死或浪费。说明已知事实、推测与缺失证据，不编百分比或完成时间。
- 用户只问一个任务就回答那个任务；资料冲突时标出冲突和各自时间，不把过时的进度快照当成实时状态。

## 转达用户的话

用户明确要求转达，或向已经确认的主任务下达明确指令时才发送；已有授权不重复询问。普通问题、讨论中的想法和你的判断不自动变成指令。保留用户原意，按需附上任务背景，不扩大范围或授权。

优先用平台确实提供的跨会话消息工具，发送给已核实的会话 ID。Codex 桌面有 `send_message_to_thread` 时可用；它可能启动新轮次，因此仅用于已授权的转达。不要把子代理消息工具当成可以联系任意独立会话的接口。

没有合适的直接通道时，只有确认该项目**仅有一个主会话记录，且目标匹配**，才用 `retro.mjs tell - --root "<项目绝对路径>"`，从标准输入传入用户的话，避免将原文拼进 shell 命令。`tell` 自动选择缓存显示 active 的最近会话，不支持指定目标；多个候选或无法确认时不用它，请用户直接到目标会话发消息。

如实说明转达到了哪一步：`tell` 成功只是**已排队**；主会话下次工具事件才会收到。对应会话、时间和文本的 `told` 事件表示 **hook 已交付**，不代表主 agent 已处理或执行。直接消息也按工具回执说明状态，不因暂时没有回复而重复发送。排队消息不能保证立即停止任务；没有即时控制通道时说明这一点，让用户在主会话停止。

排队后目标已变更，或消息缺少目标身份时，hook 会将其保存在 `.retro/user-said.md` 并标为未送达，不交给新目标。查到这类记录时如实说明，需要用户确认适用目标后才重新转达。

## 保持现场

除获授权的转达外，只读文件和状态；不运行构建、评测或探测，不派代理，不改共享记录或 goal。脚本只用 `records show`、`status`、`metrics`，不启动 watch 或恢复监控。

查询结束后直接回答，不自行进入定期轮询。上下文恢复后重新核对查看对象与证据时间，不依赖上一次快照仍然有效。
