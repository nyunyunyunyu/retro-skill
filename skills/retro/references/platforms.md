# 平台接入

只读当前使用的路径。脚本命令都带 `--root <项目绝对路径>`；主 agent 自己只运行短的管理命令。

## Codex 主 agent

- 用 `spawn_agent` 委派；新的独立任务给完整说明，通常 `fork_turns: "none"`。追问原代理用平台提供的消息或 `followup_task`。
- 用 `wait_agent` 有界等待，通常不超过 5 分钟，环境要求更短时按更短上限。等待结束先处理消息和到期复查，不忙轮询。
- 并发受平台配置和资源约束。一个执行名额也能工作，按实际可用容量安排评审，不要求固定预留数。
- hook 负责记录并在工具事件和压缩恢复时提供提醒。Stop 事件不创建 retro 的续跑轮次，继续运行由原生 goal 机制负责。
- 暂停、恢复和完成使用当前平台提供的原生目标功能。遵守其授权与状态规则；证据和必要收尾完成后再标记完成。

### 临时服务故障恢复

用户已授权“服务中断后自动继续”时，在要监控的 **Codex 桌面本机会话**运行 `node <skill>/scripts/codex-recover.mjs start --root <项目>`。它为当前 active goal 启动独立后台进程；命令确认就绪后才算启用。用同一脚本的 `status` 查看状态，`stop` 停用。每次暂停、目标改变或监控退出后，需要重新启用；同一目标已用掉的重试次数保留。

监控每 15 秒核对原生目标和最新轮次。只有会话已 idle/systemError、最新轮次明确 failed，且结构化错误属于容量不足、请求限流、内部服务错误或连接/流传输故障白名单时，才延迟 30/60/120 秒向**原会话**发送一次继续消息；每个目标最多 3 次，每个失败轮次最多一次。不会因为沉默、正常结束或后台任务耗时而唤醒。发送前再次核对目标与轮次，先登记尝试；发送结果未知时停止，避免重复。

这恢复的是 **active goal 中失败的轮次**，不改原生目标状态。goal 已 paused、受预算/额度限制、完成、清除或不可读时退出；明确安全阻止、未知错误也退出，由用户处理。“安全审查”这个称呼不能证明是临时故障，不按错误文本中的关键词放行。若服务失败同时把目标置为 paused，仍需用户用原生 `/goal resume`；当前桌面工具没有可供此脚本调用的目标恢复接口。

依赖桌面版的 `CODEX_THREAD_ID`、`CODEX_APP_TOOLS_PIPE_PATH`、本机目标数据库与 `codex-app-tools` 会话接口。它不启动第二个 Codex、不接管线程、不改模型、预算或权限。CLI、远程主机和 Claude 主 agent 不支持这项恢复。沙箱拒绝管道访问时按平台授权流程运行；缺少接口或权限时报告未启用，不宣称会自动继续。

状态在 `.retro/recovery/<会话>.json`，尝试和停止原因记入 `.retro/log.tsv`。桌面退出、管道断开或协议变化后监控停止；重开桌面后重新启用。接口没有“核对并发送”的原子操作，发送前最后一次核对与消息入队之间仍有很短的竞态窗口；恢复消息要求再次核对最新用户指令，暂停期间不得继续执行。

## Claude Code 主 agent

- 用 Agent 工具在后台委派，追问用 SendMessage，明确决定停止时用 TaskStop。
- 没有可做的协调工作时结束当前轮，等待原生 goal 和后台任务事件。需要运行监控时，按 hook 的命令用 Bash 在后台启动 `retro.mjs watch`；它发现需要判断的情况便退出，让主 agent 在后续工具事件取得提醒。
- watch 只能报告观测；主 agent 被前台工具或授权阻塞时不能抢占它。不要在主 agent 上跑长工具。
- 暂停按当前平台的 `/goal clear` 操作；恢复时使用原目标原文，先核对现场。脚本只读取目标状态，不替用户创建或重启目标。

## Claude Code 派 Codex 执行（可选）

只有用户选择这条执行路径时使用 `scripts/codex-worker.mjs`；Codex 当主 agent 时通常用原生子代理。

1. 在 `.retro/tasks/<任务>/brief.md` 写完整说明和验证预算。
2. 用 Bash 在后台运行 `node <skill>/scripts/codex-worker.mjs run <任务> --root <项目>`，需要隔离时加 `--cd <worktree>`。
3. 结束通知后读输出文件与任务回报；追问在后台运行 `resume <任务> "<话>" --root <项目>`，沿用原线程。
4. 决定停止时用 `stop <任务> --root <项目>`，避免只停外层 Bash 而留下子进程。该驱动不能在运行的一轮中直接接收追问，停止后再恢复需要权衡损失。

驱动记录事件、rollout 活动、命令和进程；静默只作为 hook 提醒的输入，不自动打断、重启或换人。默认每次 run/resume 有 120 分钟硬超时，可用 `--timeout <分钟>` 显式设定；安排长任务时把硬预算告诉执行者。硬超时或显式停止会尝试终止进程树，不能保证未落盘结果保留；驱动失联或未确认结束时核对实际进程，不能只凭状态文件宣称已停。

外部驱动的权限配置、安装要求和已知限制见仓库 README；缺少能力时说明原因，不在未授权情况下更换权限或偷偷扩大执行范围。

## 等待授权

把需要用户决定的事项和提出时间记进进度快照（默认 `.retro/PROGRESS.md`），提出一次后继续不依赖它的协调工作。遵守用户或项目的追问约定；本项目采用 30 分钟、2 小时各一次合并提醒，之后不再追问。

有合适且获授权的定时工具时建立一次性提醒，并先检查重复项；没有就说明未设定，不写成已安排。收到提醒时核对事项仍未解决、目标仍在进行，避免暂停或完成后继续追问。等待不是授权，不允许代替用户作答。
