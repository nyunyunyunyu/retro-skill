# 路线与评审

主 agent 决定路线和优先级，重要调整保留依据、成本和复查条件。假设被推翻时及时处理，不等评审批准。长程复盘、查外部经验和深入路线比较交给子代理，主 agent 保持响应。

`route-reviewer` 提供独立的路线与优先级建议；`idea-scout` 寻找替代方法、危险假设和知识缺口，复查有新证据的死路。探索投入由不确定性和预期价值决定，不设固定比例或必须产出的想法数。

安装器将这两个名字注册到 Claude 和 Codex 各自的 agent 列表，主 agent 按名字选择即可，不必把角色全文读进自己的上下文。找不到对应角色时报告安装或刷新问题，释放已占用的登记，不假装角色已经启动。

## 现有脚本协议

脚本在目标开始、后续定期复查或显式请求后登记一个后台机会，同一项目同一时刻只保留一个。按时间和结果数量选出的类型只是默认建议；主 agent 决定是否值得启动。

- 需要提前评审或侦察：`retro.mjs request review|scout --session <主会话 ID>`。请求仅由该会话当前目标消费，多个候选时不能省略会话 ID。
- 收到登记，决定启动：按提醒使用对应的专用代理，传入开始时间、脚本和项目路径；后台运行，主 agent 不等待它完成。
- 不需要、资源不足或启动失败：`retro.mjs abort <开始时间>`。取消释放登记，本轮不会立刻重新强迫启动；后续时间到期或新请求仍可提醒。
- 想改类型：先释放尚未使用的登记，再请求所需类型。
- 登记 20 分钟未启动会过期；启动后评审限 20 分钟、侦察限 40 分钟。这是交付资格期限，过期结果不能写回。需要停止代理时由主 agent 发出明确停止操作。

专用代理必须先用 `spawned` 核对登记，最后用 `finish` 交付；过期或不匹配的结果被拒绝。无活跃 goal 的单次复盘用普通执行子代理，不调用这些专用代理和登记接口。

## 使用结论

检查报告之后有没有新证据推翻它的前提。采纳、部分采纳或暂不采纳都可以，说明影响决定的理由；不确定且影响大的先派便宜的核实。建议不会自动变成任务，主 agent 不需要逐条执行。

评审有价值的是独立证据与不同视角。不要只因为到点就安排没有信息价值的复盘，也不要让主 agent 自己深入复盘而耽误用户和执行者。
