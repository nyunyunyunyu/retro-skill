# 状态与证据

`.retro/PROGRESS.md` 是简短的方向快照，优先保留仍然有效的用户约束、证据和关键决定。通常控制在约 4 KB；不能为压缩体积丢掉约束。详细过程留在任务笔记。

只有 `.retro/PROGRESS.md` 不存在时才读根目录旧版 `PROGRESS.md`；两者都有时以新路径为准，不双写。脚本兼容读取旧版，不自动搬动或合并。迁移根目录旧进度、RUNBOOK.md 或 runbook/ 时，先确认属于过程记录并核对目标路径；保留有效内容，不覆盖已有新文件，正式项目手册仍按原结构维护。

```text
# PROGRESS（YYYY-MM-DD HH:MM）
目标（同 /goal）：… · 怎么证明：…
用户指令：…
最好结果：…（版本、证据）
差距：…（已知事实与待验证假设）
路线：… · 理由：… · 复查条件：…
进行中：任务 — 执行者 / worktree — 资源 — 任务目录
下一步：…（责任人、复查时间或条件）
上次评审：时间 — 结论 — 如何处理
待授权：事项 — 原因 — 提出时间 — 已追问次数
其他：手册、想法池、积压、总表的位置
```

开始、恢复、上下文压缩后核对它与当前 goal 和运行状态。关键变化及时写；定期检查点只整理尚未处理的新结果，用 `retro.mjs inbox --session <主会话 ID>` 汇集，整理后 `retro.mjs done "<决定或核对结果>" --session <主会话 ID>` 标记。沿用 hook 给出的会话 ID；只有一个候选时可以省略，多个候选时脚本拒绝猜测。

读取位置按会话和目标分别保存在 `.retro/checkpoints/`；切换目标不会继承另一个目标的检查点。升级后无法归属的旧读取位置会被忽略，首次可能重读当前目标已有的回报。报告、总表和进度快照仍由项目共享，需要核对内容属于哪个目标。

| 文件 | 写入责任与用途 |
|---|---|
| `.retro/PROGRESS.md` | 主 agent；方向、决定和用户约束 |
| `.retro/RUNBOOK.md` 与 `.retro/runbook/` | 主 agent 指定的唯一合并者；经核实的构建、测试、评测方法和代码地图，其他执行者只读 |
| AGENTS.md | 项目规则；长期约束按用户授权和项目惯例维护 |
| `.retro/tasks/<任务>/report.md`、`notes.md` | 该任务的执行者独写；简短回报、可接手的细节及待合并的手册补充 |
| `.retro/ideas.md` | 主 agent；有价值的想法、知识缺口、死路证据与重试条件 |
| `.retro/backlog.md` | 主 agent 或明确受托的子代理；未安排的问题及影响，发现者先回报以免并发覆盖 |
| `.retro/results.tsv` 或项目已有总表 | 评测程序；时间、版本、指标、输入和证据位置 |
| `.retro/probes/` 与评审存档 | 后台代理；探测和报告，按登记协议交付 |

想法池不规定数量。合并重复、移除过时项目；用户明确要求试的优先安排。死路保留否定依据，相关条件或评测变化后再查。积压在影响验收或自然里程碑时重评，不为清单本身开启无止境工作。

## 手册汇总

执行者在各自任务的 `notes.md` 记录方法、适用条件和证据，回报时指出值得保留的补充，不并行改共享手册。影响其他任务的发现立即回报主 agent，由它转给相关执行者，不等手册合并。

任务验收、阶段检查点或收尾时，主 agent 按需要指派一名执行者，汇总已交付的笔记到 `.retro/RUNBOOK.md` 及 `.retro/runbook/`。同一时间只有这一名合并者可写；上一位结束或确认停止后才转交。合并时去重，核对版本和适用条件，保留任务与证据来源；结论冲突先标待核实并回报，不用后写的直接覆盖。原始任务笔记保留，便于追溯。

## 版本控制

过程记录默认只保存在本地：进度、任务说明、工作笔记、探测报告、评审、想法池和中间结果均不随代码提交。新记录统一放 `.retro/`，包括 PROGRESS.md 和 RUNBOOK.md。需要交付的方法或结论先整理成项目正式文档，不把流水记录直接纳入仓库。

Git 项目在写记录前运行 `retro.mjs init --root <项目绝对路径>`。它将 `.retro/` 和旧布局的 PROGRESS.md、RUNBOOK.md、runbook/、results.tsv 加入 Git 本地 `info/exclude`，按项目子目录限定范围，worktree 共用；不改项目 `.gitignore`。仓库规则抵消本地排除时会报错，需要先解决，不能把失败当作已经保护。

忽略规则对已跟踪文件无效，`init` 会列出这些路径。先按内容区分过程记录与正式交付；确认是过程记录后，用精确路径执行 `git rm --cached -- <文件>`（目录加 `-r`），保留本地内容，只取消今后的跟踪，不重写历史。不要把原有项目文档或别人暂存的交付一并移除。

提交前核对 `git diff --cached --name-only`，按具体交付路径暂存；不为保存过程记录而使用 `git add -f`。AGENTS.md 只保留项目规则，任务状态、排错经过和临时发现写入本地记录。

`.retro/` 在 worktree 间共享，委派时给绝对路径并协调写入。其余状态文件由脚本维护，不能手改；`status`、`metrics` 只读，`inbox` 会记录本轮读取时间，`slots`、`request`、`done`、`abort` 等用于显式管理。

进度台 `retro-status` 可以读取快照和任务细节；转达只在用户明确要求时进行。状态记录是观测，不能单凭提交数、日志行数或代理活动断言有价值的进展。
