# 状态与证据

PROGRESS.md 是简短的方向快照，优先保留仍然有效的用户约束、证据和关键决定。通常控制在约 4 KB；不能为压缩体积丢掉约束。详细过程留在任务笔记。

```text
# PROGRESS（YYYY-MM-DD HH:MM）
目标（同 /goal）：… · 怎么证明：…
用户指令：…
最好结果：…（版本、证据）
差距：…（已知事实与待验证假设）
路线：… · 理由：… · 复查条件：…
进行中：任务 — 执行者 / worktree — 资源 — 任务目录
下一步：…（责任人、复查时间或条件）
上次评审：时间 — 结论 — 如何处理
待授权：事项 — 原因 — 提出时间 — 已追问次数
其他：手册、想法池、积压、总表的位置
```

开始、恢复、上下文压缩后核对它与当前 goal 和运行状态。关键变化及时写；定期检查点只整理尚未处理的新结果，用 `retro.mjs inbox` 汇集，整理后 `retro.mjs done "<决定或核对结果>"` 标记。

| 文件 | 写入责任与用途 |
|---|---|
| PROGRESS.md | 主 agent；方向、决定和用户约束 |
| RUNBOOK.md 与 runbook/ | 执行者；构建、测试、评测和代码地图，按需读取 |
| AGENTS.md | 项目规则；长期约束按用户授权和项目惯例维护 |
| `.retro/tasks/<任务>/report.md`、`notes.md` | 执行者；简短回报及可接手的细节 |
| `.retro/ideas.md` | 主 agent；有价值的想法、知识缺口、死路证据与重试条件 |
| `.retro/backlog.md` | 主 agent 或明确受托的子代理；未安排的问题及影响，发现者先回报以免并发覆盖 |
| `.retro/results.tsv` 或项目已有总表 | 评测程序；时间、版本、指标、输入和证据位置 |
| `.retro/probes/` 与评审存档 | 后台代理；探测和报告，按登记协议交付 |

想法池不规定数量。合并重复、移除过时项目；用户明确要求试的优先安排。死路保留否定依据，相关条件或评测变化后再查。积压在影响验收或自然里程碑时重评，不为清单本身开启无止境工作。

`.retro/` 在 worktree 间共享，委派时给绝对路径并协调写入。其余状态文件由脚本维护，不能手改；`status`、`inbox`、`metrics` 用于查看，`slots`、`request`、`done`、`abort` 等用于显式管理。

进度台 `retro-status` 可以读取快照和任务细节；转达只在用户明确要求时进行。状态记录是观测，不能单凭提交数、日志行数或代理活动断言有价值的进展。
